# tg_username_hunter

Консольная утилита и GUI на Python для поиска коротких, читаемых и свободных Telegram username. Проверка доступности выполняется через официальный метод Telegram API `account.CheckUsername` с Pyrofork.

## Возможности

- проверка username через Telegram API, без парсинга `t.me`;
- режимы `dict`, `syllable`, `both`, `list`;
- длина username от **5 до 32** символов;
- по умолчанию используются строчные буквы `a-z`;
- опционально можно разрешить цифры `0-9` и символ `_`;
- локальная оценка «красоты» от 0 до 100 с учётом узнаваемости слова/основы;
- учитываются длина, читаемость, баланс гласных/согласных, повторы, цифры и `_`;
- кандидаты ниже `min_score` не отправляются в Telegram API;
- кандидаты сортируются по score, лучшие проверяются первыми;
- уведомления о найденных **напрямую доступных** username через Telegram-бота;
- Bot API работает в отдельном worker-потоке и не блокирует основной поиск;
- полностью переработанный GUI на **Bootstrap 5.3.8** внутри desktop-окна `pywebview`;
- адаптивная Bootstrap-сетка: интерфейс автоматически перестраивается при ручном изменении размера окна;
- GUI на русском и английском языках;
- состояние результатов GUI сохраняется при переключении языка;
- результаты не сохраняются в локальные `found*.txt` — источник уведомлений о находках один: Telegram-бот;
- единый ротационный лог ошибок для GUI и CLI с диагностикой Telegram RPC/Bot API/network/worker ошибок и реальных пропусков username.

## Требования

Python 3.10+. Зависимости перечислены в `requirements.txt`.

```bash
pip install -r requirements.txt
```

Pyrofork предоставляет совместимые импорты `pyrogram`, поэтому в исходниках используется namespace `pyrogram`.

## Настройка

Получите `api_id` и `api_hash` на `my.telegram.org` → **API development tools**.

Настройки хранятся в локальном `config.py` рядом со скриптом или EXE. Безопасный шаблон находится в `config.example.py`.

```python
TG_API_ID = "123456"
TG_API_HASH = "abcdef0123456789abcdef0123456789"
TG_BOT_TOKEN = "123456:token"
TG_NOTIFY_CHAT_IDS = "111111111,222222222"
```

`config.py` содержит секреты, исключён через `.gitignore` и не должен попадать в Git, релизы или ZIP-архивы. GUI не создаёт `config.py` автоматически из переменных среды или Windows Registry: файл появляется только после ручного сохранения введённых пользователем данных либо уже существует рядом с программой. Каждый получатель уведомлений должен сначала отправить боту `/start`.

Telegram-сессия GUI хранится отдельно в `%LOCALAPPDATA%\TGUsernameHunter` на Windows.

## Лог ошибок

GUI и CLI используют один ротационный журнал. На Windows он находится здесь:

```text
%LOCALAPPDATA%\TGUsernameHunter\logs\tgh.log
```

На Linux/macOS используется `$XDG_STATE_HOME/tg_username_hunter/tgh.log`, а если `XDG_STATE_HOME` не задан — `~/.local/state/tg_username_hunter/tgh.log`.

В журнал попадают:

- реальные Telegram API ошибки и причины пропуска username;
- `USERNAME_INVALID` не считается ошибкой приложения: такой кандидат помечается как «недоступен» и поиск продолжается без WARNING;
- `FloodWait` с длительностью ожидания;
- Telegram `RPCError` и traceback для неожиданных сбоев;
- ошибки Bot API, HTTP/429 и сетевые ошибки;
- ошибки подключения и авторизации GUI;
- ошибки search/notification worker-потоков;
- необработанные исключения главного и фоновых потоков.

Лог ротируется автоматически: один файл ограничен **2 МБ**, сохраняется до **5** предыдущих копий. CLI дополнительно печатает путь к логу в начале поиска. Секреты конфигурации намеренно не записываются в диагностические сообщения.

В GUI кнопка **«Лог» / «Log»** находится в верхней панели и доступна на каждом экране. Она открывает текущий `tgh.log` в системном приложении.

## Консольный запуск

Без аргументов открывается интерактивное меню:

```bash
python tgh.py
```

Прямой запуск:

```bash
python tgh.py --mode both --min-len 5 --max-len 12 --limit 200 --min-score 70
```

Без ограничения по количеству проверок (до `Ctrl+C`):

```bash
python tgh.py --mode both --limit 0 --min-score 80
```

Только кандидаты с оценкой не ниже 80:

```bash
python tgh.py --mode both --min-len 5 --max-len 16 --limit 200 --min-score 80
```

С цифрами и `_`:

```bash
python tgh.py --mode both --min-len 5 --max-len 20 --limit 300 --min-score 75 --allow-digits --allow-underscore
```

Проверка собственного списка:

```bash
python tgh.py --mode list --words nova7,nova_x,echoo --allow-digits --allow-underscore --min-score 0
```

### CLI-флаги

| Флаг | Описание | По умолчанию |
|---|---|---|
| `--mode` | `dict` / `syllable` / `both` / `list` | `both` |
| `--words` | список username через запятую для `list` | — |
| `--min-len` | минимальная длина, 5–32 | `5` |
| `--max-len` | максимальная длина, 5–32 | `12` |
| `--limit` | число кандидатов, 0–10000; `0` = без лимита до ручной остановки | `100` |
| `--delay` | пауза между Telegram API запросами, сек, >= 0 | `1.0` |
| `--allow-digits` | разрешить цифры `0-9` | выкл. |
| `--allow-underscore` | разрешить `_` | выкл. |
| `--min-score` | минимальная оценка красоты 0–100 | `70` |

Свободные username печатаются в консоль и отправляются через Telegram-бота. Локальные result-файлы не создаются.

## GUI

```bash
python tgh_gui.py
```

GUI полностью переработан на Bootstrap 5.3.8 и отображается внутри desktop-окна через `pywebview`. Интерфейс остаётся нативно запускаемым через Python/EXE, но разметка и адаптивность реализованы HTML/CSS/Bootstrap.

GUI предоставляет те же параметры, что и CLI:

- режим поиска;
- длина 5–32;
- количество проверок; значение **`0` отключает лимит**, и генератор продолжает проверку до нажатия «Остановить»;
- задержка;
- `min_score`;
- разрешение цифр;
- разрешение `_`;
- отдельный переключатель **«Username для ботов»** — при включении проверяются только варианты с окончанием `bot`; при разрешённом `_` генератор также смешивает варианты вида `name_bot`;
- собственный список username (в bot-режиме основы без `bot` автоматически получают этот суффикс).

Сетевые уведомления Bot API отправляются через отдельную очередь. Ошибки worker-потока отображаются в интерфейсе. Переключение RU/EN во время поиска не очищает уже показанные результаты и прогресс. После завершения, остановки или ошибки поиска появляется кнопка **«Новый поиск»**, возвращающая к настройкам без повторной авторизации. При `0` прогресс отображается как бесконечный/неопределённый до ручной остановки.

## Сборка EXE

Для Windows используется `build_exe.cmd`. Скрипт автоматически:

Во время запуска вывод сборки отображается в консоли в реальном времени и одновременно записывается в `build_exe.log`. При ошибке окно остаётся открытым.

> `build_exe.cmd` собирает frontend из изолированной `.build_stage` по абсолютному пути, поэтому расположение `.spec` не влияет на включение папки `web` в EXE.

1. находит Python 3;
2. создаёт `.venv`, если виртуального окружения ещё нет;
3. активирует `.venv`;
4. устанавливает/обновляет зависимости из `requirements.txt` внутри `.venv`;
5. полностью удаляет предыдущие `build`, `dist`, `.pyinstaller`, `.spec` и `__pycache__`;
6. создаёт отдельную `.build_stage` из `tgh.py`, `tgh_gui.py` и Bootstrap frontend-папки `web`, без `config.py`;
7. выполняет новую чистую сборку GUI через PyInstaller, включая frontend-ресурсы и `pywebview`;
8. проверяет, что `dist\config.py` не был создан.

Запуск из `cmd.exe`:

```bat
build_exe.cmd
```

Готовый файл появляется в:

```text
dist\TG_Username_Hunter.exe
```

`config.py` не используется как входной файл сборки, не копируется в `dist` и не встраивается в EXE. При первом запуске GUI остаётся пустым, если рядом с EXE нет уже существующего локального `config.py`. Переменные среды/Registry сами по себе больше не приводят к созданию заполненного файла.

## Проверка проекта

```bash
python test_tgh.py
```

Тест проверяет конфигурацию, фильтрацию длины, digits/underscore, lexical scoring (включая отсечение псевдослов при 80+), генерацию, остановку FloodWait, уведомления и запись диагностических ошибок в ротационный лог.

## Как работает scoring

1. Генерируются словарные и/или слоговые кандидаты.
2. Проверяется Telegram-формат и выбранные ограничения.
3. Для каждого кандидата рассчитывается `score_username()` от 0 до 100: кроме длины и читаемости учитывается лексическая узнаваемость основы. Случайные псевдослова не могут получить 80+ только за счёт удачного чередования гласных и согласных.
4. В оценку входят длина, баланс гласных/согласных, читаемость, повторения, разнообразие символов и штрафы за цифры/`_`.
5. Кандидаты ниже `min_score` отбрасываются локально.
6. Оставшиеся сортируются по score и только затем отправляются в Telegram API.
7. Напрямую доступные username отправляются получателям через Telegram-бота.
