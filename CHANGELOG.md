# Changelog

## [1.2.0] - 2026-08-19

### Новое

- Полностью переработан GUI: CustomTkinter заменён на Bootstrap 5.3.8 frontend внутри desktop-окна `pywebview`.
- Поле количества проверок принимает `0`: в генерируемых режимах это запускает поиск без лимита до ручной остановки.
- После завершения/остановки/ошибки поиска появляется кнопка **«Новый поиск»** для возврата к настройкам без повторной авторизации.
- В режиме без лимита прогресс отображается как неопределённый, а счётчик проверенных username продолжает расти.

### Интерфейс

- Новая адаптивная Bootstrap-сетка, карточки параметров, метрики результатов, responsive layout и единая верхняя панель.
- Кнопка открытия лога доступна на всех экранах.
- Состояние параметров и результатов сохраняется при переключении RU/EN.
- Возвращена кликабельная ссылка `github.com/BYxarek` в футер Bootstrap GUI с указанием доработки проекта.
- Добавлен отдельный статус «недоступен» / `unavailable` для зарезервированных/неназначаемых username.

### Проверка username

- `USERNAME_INVALID` больше не считается ошибкой приложения и не попадает в `пропущен`: кандидат получает статус «недоступен».
- `USERNAME_OCCUPIED`, если Pyrofork возвращает его как RPCError, явно классифицируется как «занят».
- Реальные RPC/сетевые ошибки по-прежнему фиксируются в общем журнале.

### Сборка

- `requirements.txt`: `customtkinter` заменён на `pywebview==6.2.1`.
- `build_exe.cmd` создаёт/активирует `.venv`, устанавливает зависимости и выполняет полностью чистую сборку.
- Добавлен `build_exe.log` с полным stdout/stderr, версиями Python/pip/PyInstaller и `pip freeze`.
- Вывод сборки одновременно показывается в консоли в реальном времени и сохраняется в лог.
- Исправлен путь `--add-data` для Bootstrap frontend: используется абсолютный путь к `.build_stage\web`.
- Сохранена staging-сборка без `config.py` и локальных секретов.
- Окно CMD остаётся открытым после успешной или неуспешной сборки.

### Ядро

- Добавлен потоковый `iter_candidates()`: `limit=0` используется как режим без ограничения для генератора.
- CLI поддерживает `--limit 0`; остановка выполняется через `Ctrl+C`.

### Тесты

- Добавлена регрессия: `UsernameInvalid` обязан возвращать `unavailable`, а не `None`.
- Добавлена проверка наличия ссылки `github.com/BYxarek` в Bootstrap frontend.

Все заметные изменения проекта фиксируются в этом файле.

## [1.1.7] - 2026-08-19

### Исправлено

- Убран большой пустой вертикальный промежуток на экране результатов между текущим проверяемым username и списком проверенных ников.
- Причина была в пустом `CTkFrame` для сообщений об ошибках: CustomTkinter создавал его с большой высотой по умолчанию даже когда ошибок не было.
- Пустые контейнеры ошибок на экранах подключения, телефона, кода, 2FA и результатов теперь имеют минимальную высоту и расширяются только при появлении текста ошибки.

## [1.1.6] - 2026-08-19

### Исправлено

- Исправлен scoring красоты: прежняя формула переоценивала случайные фонетические псевдослова (`zumiyim`, `iqahyew` и подобные), потому что учитывала в основном длину и баланс гласных/согласных.
- В `score_username()` добавлена сильная лексическая составляющая: узнаваемые слова и естественные комбинации известных основ получают высокий балл, случайные псевдослова — нет.
- Порог `min_score=80+` теперь фактически означает узнаваемое слово/естественную комбинацию; случайная произносимая строка не проходит только из-за удачной фонетики.
- Bot usernames оцениваются по смысловой основе без обязательного суффикса `bot`/`_bot`, поэтому `cloudbot` сохраняет качество основы `cloud`.

### Тесты

- Добавлены регрессии для `zumiyim` и `iqahyew`: их score обязан быть ниже 80.
- Добавлена проверка, что `cloud` и `novacore` получают 80+, а выборка `both` с `min_score=80` не содержит кандидатов без лексической основы.

## [1.1.5] - 2026-08-19

### Добавлено

- В GUI добавлен отдельный переключатель **«Username для ботов» / «Bot usernames»**.
- При включении режима генератор отдаёт только username с обязательным окончанием `bot`.
- При разрешённом `_` часть сгенерированных вариантов получает форму `name_bot`, при этом шаблон смешивается с обычным `namebot`, а не используется для всей очереди подряд.
- В режиме собственного списка введённые основы без `bot` автоматически нормализуются добавлением суффикса `bot`; уже готовые bot-username остаются без изменений.

### Тесты

- Self-check проверяет обязательное окончание `bot`, диапазон длины, валидность Telegram-формата, наличие `_bot` при разрешённом `_` и нормализацию собственного списка.

## [1.1.4] - 2026-08-19

### Добавлено

- Кнопка **«Лог» / «Log»** в постоянной шапке GUI; она доступна на каждом экране и открывает общий `tgh.log` в системном приложении.
- Расширен словарный пул узнаваемыми популярными английскими основами (`cloud`, `music`, `design`, `gaming`, `space`, `travel`, `tech` и др.).

### Изменено

- Генератор больше не перебирает словарь сериями с одинаковым суффиксом вроде `word_io`.
- Словарный режим сначала перемешивает обычные слова, затем создаёт случайные комбинации из разных основ и коротких частей.
- При разрешённом `_` правая часть выбирается из разнообразного пула; при разрешённых цифрах используется случайная цифра вместо последовательного перебора `0..9`.
- Кандидаты с одинаковыми score и длиной перемешиваются вместо алфавитной сортировки, поэтому очередь проверки выглядит разнообразнее.

### Тесты

- Self-check проверяет, что генерация не деградирует в повторяющуюся серию `_io` и содержит несколько разных типов кандидатов.

## [1.1.3] - 2026-08-19

### Добавлено

- Единый ротационный журнал `tgh.log` для GUI и CLI.
- В лог записываются Telegram RPC errors, `UsernameInvalid`, `FloodWait`, все пропуски username, ошибки Bot API, сетевые ошибки, ошибки авторизации GUI, ошибки worker-потоков и необработанные исключения.
- Для неожиданных исключений сохраняется traceback, чтобы можно было определить точное место сбоя.
- Лог ограничен 2 МБ на файл и хранит до 5 резервных копий (`tgh.log.1` … `tgh.log.5`), поэтому не растёт бесконечно.
- CLI при запуске печатает полный путь к текущему файлу лога.

### Диагностика

- На Windows общий лог GUI/EXE и CLI хранится в `%LOCALAPPDATA%\TGUsernameHunter\logs\tgh.log`.
- На Linux/macOS используется `$XDG_STATE_HOME/tg_username_hunter/tgh.log` либо `~/.local/state/tg_username_hunter/tgh.log`.
- Расширен self-check: он проверяет запись в лог и диагностирование непредвиденной ошибки проверки username.

## [1.1.2] - 2026-08-19

### Исправлено

- Уменьшен базовый размер GUI с `600x860` до `600x690`; минимальная высота снижена до `640`.
- При расширении окна боковые отступы теперь адаптируются автоматически, а рабочая область остаётся компактной и центрированной вместо чрезмерного растягивания элементов.
- Футер/копирайт остаётся у нижней границы окна без большого пустого пространства при стандартном размере.
- Исправлено автоматическое создание заполненного `config.py`: GUI больше не использует переменные среды или Windows Registry как основание для автоподключения и последующего сохранения секретов.
- Поля GUI автоматически заполняются только из уже существующего локального `config.py`.

### Безопасность сборки

- `build_exe.cmd` теперь собирает EXE из отдельного `.build_stage`, куда копируются только `tgh.py` и `tgh_gui.py`.
- Локальный `config.py` физически не попадает в staging-каталог и не используется PyInstaller как входной файл.
- После сборки скрипт отдельно проверяет отсутствие `dist\config.py`.

## [1.1.1] - 2026-08-19

### Изменено

- `build_exe.bat` заменён на `build_exe.cmd`.
- Сборочный скрипт создаёт `.venv`, если окружения ещё нет, и активирует его перед всеми командами сборки.
- Зависимости устанавливаются/обновляются только внутри `.venv`.
- Перед PyInstaller выполняется полная очистка старых `build`, `dist`, `.pyinstaller`, `.spec` и `__pycache__`, поэтому каждый EXE собирается заново.
- Скрипт проверяет наличие итогового `dist\TG_Username_Hunter.exe` и возвращает ненулевой код при ошибке.

## [1.1.0] - 2026-08-19

### Добавлено

- Единый контракт `prepare_candidates()` для CLI, GUI и тестов.
- Поддержка длины Telegram username 5–32 символа.
- Флаги `--allow-digits` и `--allow-underscore` в CLI.
- Аналогичные переключатели digits/underscore в GUI.
- `score_username()` с оценкой 0–100.
- Порог `--min-score` в CLI и поле минимального score в GUI.
- Сортировка кандидатов по score до обращения к Telegram API.
- `BotNotificationWorker`: отдельная очередь и поток для Bot API уведомлений.
- Отображение ошибок поиска/worker-потока непосредственно в GUI.
- Сохранение состояния результатов и прогресса при переключении языка GUI.
- `config.example.py` без секретов.
- `build_exe.bat` для сборки Windows EXE.

### Исправлено

- `mode=list` теперь соблюдает `min_len`/`max_len`.
- Исправлено расхождение сигнатуры `prepare_candidates()` с тестами.
- GUI и CLI синхронизированы с описанными в README параметрами.
- Отрицательная задержка CLI теперь отклоняется валидатором аргументов.
- Добавлены проверки диапазонов `limit` и `min_score`.
- Ошибка фонового GUI worker больше не теряется только в stdout.
- Переключение RU/EN больше не очищает список уже проверенных username.

### Изменено

- Удалено локальное сохранение результатов в `found.txt` / `found_fragment.txt`.
- Удалён CLI-флаг `--output`.
- Для найденных напрямую доступных username используется Telegram bot notification в CLI и GUI.
- Bot API больше не блокирует основной цикл проверки username.
